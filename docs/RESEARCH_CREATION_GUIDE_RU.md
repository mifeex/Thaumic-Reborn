# Создание исследований для Thaumic Reborn

Исследования создаются как JSON-ресурсы. Для нового узла не нужно менять
Java-код или экран Таумономикона.

## Где находятся файлы

Каждое исследование хранится отдельным файлом:

```text
src/main/resources/data/thaumic_reborn/thaumcraft/research/<имя>.json
```

Переводы заголовков, описаний и страниц находятся здесь:

```text
src/main/resources/assets/thaumic_reborn/lang/ru_ru.json
src/main/resources/assets/thaumic_reborn/lang/en_us.json
```

Production-примеры:

```text
first_discovery.json
basics.json
```

Служебная категория `research` и определения `test_research_*` удалены из
production resources. `first_discovery` и зависимый `basics` находятся в
классической категории `basics`. Для экспериментов создавайте отдельный
datapack или содержательные production ID, не возвращайте тестовую ветку в
сборку.

## Минимальное ручное исследование

```json
{
  "id": "my_first_research",
  "category": "basics",
  "icon": "minecraft:paper",
  "title": "research.thaumic_reborn.my_first_research.title",
  "subtitle": "research.thaumic_reborn.my_first_research.subtitle",
  "completion_warp": 0,
  "concealed": false,
  "auto_unlock": false,
  "parents": [],
  "x": 0,
  "y": 0,
  "pages": [
    {
      "type": "text",
      "title": "research.thaumic_reborn.my_first_research.page.title",
      "body": "research.thaumic_reborn.my_first_research.page.body"
    }
  ]
}
```

Для него нужно добавить четыре строки в оба файла локализации:

```json
"research.thaumic_reborn.my_first_research.title": "Название",
"research.thaumic_reborn.my_first_research.subtitle": "Короткое описание",
"research.thaumic_reborn.my_first_research.page.title": "Заголовок страницы",
"research.thaumic_reborn.my_first_research.page.body": "Текст страницы"
```

Следите за запятыми: JSON должен оставаться валидным.

## Основные поля

| Поле | Назначение |
| --- | --- |
| `id` | Уникальный постоянный ID. После выпуска его лучше не переименовывать. |
| `category` | ID вкладки. Для стартовой progression используется `basics`. |
| `icon` | ID предмета, который рисуется внутри узла. |
| `icon_resource` | Альтернатива `icon`: полный ResourceLocation классической 32×32 PNG. Одновременно задавать оба нельзя. |
| `title` | Ключ локализации названия. |
| `subtitle` | Ключ локализации краткого описания. |
| `completion_warp` | Количество искажения, которое сервер один раз выдаёт игроку при завершении исследования. |
| `concealed` | Если `true`, узел не показывается до выполнения родителей и условия появления. |
| `auto_unlock` | Если `true`, исследование завершается автоматически и записка для него не создаётся. |
| `inactive` | Если `true`, запись показывается как архивная, но исследовать её нельзя. |
| `virtual` | Если `true`, ID участвует в progression, но отдельный узел и страницы в книге не рисуются. |
| `parents` | Исследования, которые нужно завершить. Между узлами рисуются линии. |
| `hidden_parents` | Обязательные исследования без линий в дереве. |
| `revealed_by` | Дополнительный ID исследования, которое должно быть завершено. |
| `x`, `y` | Положение узла относительно центра поля. |
| `node_style` | JSON-настройка классической рамки узла и специальной накладки. |
| `pages` | Страницы, доступные после завершения исследования. |

Классическая форма иконки полностью задаётся в JSON:

```json
"node_style": {
  "frame": "round",
  "special": false
}
```

Допустимые рамки: `primary` (квадратная), `round` (круглая),
`secondary` (шестиугольная) и `hidden` (скрытая). `special: true`
добавляет поверх основной рамки классическую золотую специальную накладку.
У импортированных исследований без `node_style` форма автоматически
берётся из сохранённых флагов TC4 `legacy.flags`; явно заданный
`node_style` всегда имеет приоритет.

Для обычного исследования, которое должно выдавать записку по ПКМ, оставляйте:

```json
"auto_unlock": false,
"inactive": false
```

Поле `inactive` можно вообще не указывать — по умолчанию оно равно `false`.

## Искажение за исследование

Автор исследования может назначить точное количество искажения прямо в JSON:

```json
"completion_warp": 3
```

Значение должно быть целым неотрицательным числом. Если поле отсутствует или
равно `0`, исследование не выдаёт искажение. При значении больше нуля вокруг
узла рисуется классическая фиолетовая аура запретного знания, а при наведении
показывается точное количество искажения.

Искажение выдаётся сервером только один раз — в момент завершения или покупки
исследования. Повторная синхронизация уже завершённого исследования не выдаёт
его снова. Для импортированных исследований TC4 без явного `completion_warp`
сохраняется совместимость: значение берётся из первого числа `legacy.warp`.
Явное поле `completion_warp` имеет приоритет над импортированным значением.

## Как построить цепочку

Исследование, доступное после `my_first_research`:

```json
"parents": [
  "my_first_research"
]
```

Исследование, которому нужны сразу две ветви:

```json
"parents": [
  "left_branch",
  "right_branch"
]
```

Если закрытый узел должен быть виден заранее, используйте:

```json
"concealed": false
```

Он появится в дереве сразу, но будет недоступен до завершения родителей.

Если узел должен полностью появиться только после родителей:

```json
"concealed": true
```

`concealed` является самостоятельным классическим флагом и не выводится из
наличия `parents` или `hidden_parents`. Переносимая запись должна сохранять
точное значение TC4: родительский узел может быть виден заранее и оставаться
недоступным до выполнения dependencies.

Для временного просмотра всего дерева не меняйте сотни JSON. Используйте
`research.debugShowAllResearch = true` в
`config/thaumic_reborn-client.toml`. Debug-параметр меняет только
отображение и ничего не открывает игроку.

## Координаты

Координаты считаются от центра рабочей области:

- `x: 0, y: 0` — центр;
- положительный `x` двигает узел вправо;
- отрицательный `x` — влево;
- положительный `y` — вниз;
- отрицательный `y` — вверх.

Для текущего размера узлов удобно начинать с шага 40–48 логических пикселей:

```text
первый узел:   x = -48, y = 0
второй узел:   x =   0, y = 0
ветвь сверху:  x =  48, y = -32
ветвь снизу:   x =  48, y =  32
```

Положение можно менять только в JSON. Пересборка Java-кода для этого не нужна.

## Страницы

Текстовая страница:

```json
{
  "type": "text",
  "title": "research.thaumic_reborn.example.page.title",
  "body": "research.thaumic_reborn.example.page.body"
}
```

Страница существующего рецепта:

```json
{
  "type": "recipe",
  "title": "research.thaumic_reborn.example.recipe.title",
  "recipe": "minecraft:book"
}
```

`recipe` должен содержать настоящий ID рецепта, а не ID предмета.

Классическая составная страница NODEJAR:

```json
{
  "type": "compound_crafting",
  "title": "",
  "recipe": "thaumic_reborn:node_jar_capture"
}
```

Она читает runtime descriptor 3×4×3 и стоимость шести прималов, а не
дублированный screenshot.

## Дополнительные условия

`reveal_when` отвечает за первое появление узла, а `unlock_when` — за
доступность уже появившегося узла.

Пример исследования, которое становится доступным после сканирования камня:

```json
"unlock_when": {
  "type": "scan",
  "id": "block:minecraft:stone"
}
```

Пример нескольких условий:

```json
"unlock_when": {
  "type": "all_of",
  "conditions": [
    {
      "type": "aspect_known",
      "id": "aer"
    },
    {
      "type": "aspect_amount",
      "id": "aer",
      "minimum": 3
    }
  ]
}
```

Поддерживаются `always`, `all_of`, `any_of`, `not`,
`research_completed`, `research_revealed`, `scan`, `scan_aspect`, `aspect_known`,
`aspect_amount`, `warp` и `criterion`.

## Как проверить исследование в игре

1. Соберите мод и зайдите в мир.
2. Возьмите Таумономикон и откройте вкладку «Исследования».
3. Положите в инвентарь бумагу и письменные принадлежности с чернилами.
4. Доступный ручной узел должен мигать янтарным цветом.
5. Наведите курсор: появится статус «Готово к исследованию».
6. Нажмите ПКМ по узлу. Одна бумага и одна единица чернил будут потрачены.
7. Положите полученные записки и письменные принадлежности в Стол исследований.
8. Решите гекс-пазл, заберите полученное Открытие и используйте его ПКМ.
9. Снова откройте Таумономикон: зависимые узлы должны стать доступными.

Завершение ручного исследования проходит только через
`ResearchCompletionService`. Решённые сервером Notes создают player-owned
claim, а Discovery получает согласованные `Research`, `DiscoveryVersion=1` и
`ValidatedResearch`. Предмет только с `Research`, рассогласованный payload или
Discovery без claim безопасно отклоняются. Автоматической миграции legacy
Discovery нет; NBT v3 player knowledge мигрирует из v1/v2 отдельно и не
доказывает решение Notes.

При изменении JSON во время запущенного мира используйте `/reload`, затем
закройте и снова откройте Таумономикон. При изменении локализации надёжнее
перезапустить клиент.

Завершённые ID сохраняются в данных игрока. Для повторного теста всей ветки
используйте нового игрока/новый мир либо создайте исследования с новыми ID.

## Текущее ограничение

Сейчас все ручные исследования используют один общий тестовый гекс-пазл
`Aer → Lux → Ignis → Potentia → Ordo`. Индивидуальная схема аспектов пока не
задаётся в JSON. ID записки, зависимости, появление и завершение при этом
работают отдельно для каждого исследования.
