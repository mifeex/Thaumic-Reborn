## Главная цель

Создать максимально близкий к классическому Thaumcraft 4 порт для Minecraft
1.20.1. Внешний вид, звуки, исследования, аспекты, Таумометр, стол исследований
и Таумономикон должны повторять оригинальный Thaumcraft, а не использовать
условно похожие современные элементы.

В качестве главного референса используются код, ресурсы и поведение
Thaumcraft 4.2.3.5 для Minecraft 1.7.10.

## Правила работы над проектом

- При каждом изменении поднимать `mod_version` в `gradle.properties`.
- После успешной сборки копировать новый JAR в:
  `/Users/evgenii/Library/Application Support/minecraft/mods`.
- Предыдущий JAR перемещать в `/Users/evgenii/.Trash`, чтобы Forge не загружал
  одновременно две версии.
- Проверять:
  - `./gradlew clean test build runGameTestServer --console=plain`
  - unit-тесты;
  - GameTest;
  - совпадение SHA-256 собранного и установленного JAR.
- Компиляция и GameTest не подтверждают визуальную посадку клиентского GUI.
  После визуальных изменений нужен скриншот из игры.
- Использовать оригинальные ресурсы только с подтверждённым происхождением.
- Не заменять классический GUI обычными vanilla-кнопками и панелями.

### Аспекты и стол исследований

- Реализован каталог аспектов с простыми и составными аспектами.
- Составные аспекты создаются из компонентов.
- Первое открытие составного аспекта даёт 3 единицы.
- Повторное создание даёт 1 единицу.
- Сервер авторитетно проверяет комбинацию и списывает компоненты.
- Выбранные компоненты сохраняют позиции.
- При повторном выборе заменяется последний выбранный компонент:
  `aqua + terra`, затем выбор `aqua` даёт `aqua + aqua`.
- ЛКМ и ПКМ поддерживаются в интерфейсе стола.
- Аспекты можно перетаскивать в головоломку.
- Свободная целевая клетка подсвечивается светлым цветом.
- Аспект разрешено поставить в любую свободную клетку.
- Несвязанный аспект отображается серым.
- Связь считается допустимой симметрично: составной аспект может быть
  поставлен до простого и наоборот.
- Если количество аспекта становится равным нулю, он темнеет, но не исчезает.
- Когда количество снова становится больше нуля, возвращается исходный цвет.
- При размещении расходуется одна единица аспекта, а не весь запас.
- Разные звуки используются для успешной и неуспешной комбинации.
- Используются оригинальные звуки TC4:
  - выбор — `hhoff`;
  - кнопка — `cameraclack`;
  - успешное действие — `hhon`;
  - письмо — `write`;
  - удаление — `erase`.
- Кнопка объединения не мигает целиком. Мигает только центральная точка.
- Точка сдвинута на 1 пиксель влево и вверх и имеет мягкое свечение.
- Головоломка исследований скрыта, если в столе нет письменных принадлежностей.
  Создание аспектов при этом остаётся доступным.
- В код добавлено диагностическое логирование пайплайна стола исследований.

### Сканирование Таумометром

- Поддерживается сканирование:
  - блоков;
  - предметов;
  - выброшенных в мире предметов;
  - сущностей и животных;
  - жидкостей, включая воду и лаву;
  - целей с explicit TC4-derived scan JSON;
  - эвристического fallback-контента только при явном включении
    `[scanning].automaticScanFallback=true` в server config.
- По умолчанию automatic fallback выключен. Отсутствующая definition даёт
  «Этот предмет нельзя изучить», а уже сохранённые scan keys продолжают
  читаться после выключения compatibility-режима.
- Сервер проверяет цель и результат сканирования.
- Уже изученный объект недоступен для повторного изучения.
- Уже изученный объект сразу показывает его аспекты.
- Для нового объекта сканирование завершается полностью при удержании цели.
- Сканирование не должно искусственно подсвечивать блок.
- На Таумометре показывается имя текущего блока или сущности.
- Если объект не имеет аспектов, выводится анимированный текст без фона:
  `Этот предмет нельзя изучить`.
- Если не хватает знаний, выводится текст:
  `Вам не хватает знаний для изучения этого предмета. Сначала изучите: ...`
- Проверка знаний рекурсивно учитывает компоненты сложных аспектов.
- После изучения показываются аспекты именно отсканированного объекта, а не
  общий запас игрока.
- Убраны стандартные toast-всплывашки и hotbar-сообщения во время сканирования.
- Добавлены оригинальные звуки Таумометра.
- Добавлено диагностическое логирование сканирования.

### Стабилизация исследований

- `ResearchCompletionService` является единственной серверной точкой ручного
  завершения исследования.
- Discovery принимается только при согласованном versioned payload и
  player-owned server claim о действительно решённых Notes.
- Повторно проверяются ID, `inactive`, `auto_unlock`, revealed state,
  `parents`, `hidden_parents`, reveal/unlock conditions и повторное завершение.
- Legacy Discovery только с `Research` безопасно отклоняется; автоматической
  миграции предметов нет.
- Служебная категория `research` и пять `test_research_*` записей удалены из
  production. Legacy research с ID `research` сохранён.

### First-person Таумометр

Визуальная основа версии `1.4.21`, включённая в `1.4.22`:

- Плоская first-person картинка заменена настоящей Forge OBJ-моделью
  `scanner.obj`.
- Исходные 24 faces золотого корпуса сохранены.
- Синий экран добавлен отдельной плоскостью и отдельным материалом
  `scanscreen`, повторяя второй render pass оригинального
  `ItemThaumometerRenderer`.
- После скриншота 1.4.18 плоскость экрана увеличена примерно на 5%:
  с `2.5×2.5` до `2.62×2.62`.
- Активные `textures/item/scanner.png` 256×256 и `item/scanscreen.png`
  128×128 извлечены из эталонного TC4 JAR и побайтно совпадают с оригиналом.
  Копии в `textures/models` сохранены для provenance; material variables
  ссылаются на `textures/item`, потому что именно эти каталоги прошиваются в
  item-atlas Minecraft 1.20.1.
- Искусственный 2× upscale больше не используется моделью, поэтому ранее
  внесённое интерполяционное размытие не переносится на 3D-корпус.
- Имя цели, аспекты и прогресс остаются отдельным динамическим слоем поверх
  экрана модели.
- Добавлен двухручный вид по аналогии с vanilla map rendering.
- Руки выводятся через `PlayerRenderer`.
- Цвет кожи и рукава берутся из активного скина игрока.
- Обычный first-person item render обеих рук отменяется, пока игрок держит
  Таумометр.
- Положение рук больше не зависит от наклона камеры: обе руки закреплены под
  нижними углами Таумометра и не должны исчезать при взгляде прямо.
- Рамка Таумометра, синее стекло и внутренняя область считывания увеличены ещё
  на 20% относительно версии 1.4.9. Корпус слегка заходит поверх рук игрока.
- Максимальный видимый размер 3D-корпуса сохранён равным `336×292`
  GUI-пикселя. `MODEL_VISIBLE_WIDTH/HEIGHT` компенсируют неполное заполнение
  стандартной item-области моделью.
- Большой first-person overlay отделён от third-person item transform.
  В виде от третьего лица Таумометр использует стандартную компактную посадку
  блока в правой или левой руке.
- Third-person продолжает использовать тот же OBJ с отдельным экраном и
  компактные display transforms.
- Third-person модель центрирована относительно обеих рук:
  `translation.x=0` справа и слева.
- Корневое преобразование толщины направляет к камере лицевую сторону корпуса
  с рунами и кристаллами, а не гладкую обратную сторону.
- GUI-transform не содержит дополнительного сдвига: корневая трансляция OBJ
  уже центрирует модель в стандартной item-области. Это не даёт большому
  first-person масштабу усиливать полублочное смещение влево и вниз.
- First-person корпус, стекло и динамический readout отцентрированы по экрану:
  `FRAME_OFFSET_X=0`, `FRAME_OFFSET_Y=0`.
- При ударе обе first-person руки и весь Таумометр используют одну swing-кривую.
  3D-корпус, экран, аспекты и прогресс сканирования смещаются и
  поворачиваются синхронно с руками, затем возвращаются точно в исходную позу.
- Запуск сканирования по ПКМ возвращает `CONSUME`, а не клиентский `SUCCESS`.
  Поэтому удерживаемое исследование блока, сущности или предмета не запускает
  одноразовый взмах руки. Уже изученная цель возвращает `PASS`.
- `getUseAnimation` возвращает `UseAnim.NONE`, поэтому удержание сканирования
  также не переводит third-person модель игрока в позу натягивания лука.

Последнее изменение прошло компиляцию и серверные тесты, но положение рук
нужно проверить клиентским скриншотом. Если руки находятся неверно, настраивать
трансформации в:

`src/main/java/com/thaumcraftmodern/client/ClientRenderEvents.java`

Экранный размер 3D-корпуса и область readout настраиваются в:

`src/main/java/com/thaumcraftmodern/client/ClientThaumometerOverlay.java`

### Таумономикон

- Реализованы классические боковые вкладки.
- Активные и неактивные вкладки используют один стиль, но разный tint.
- Запоминается последняя открытая вкладка.
- При следующем открытии Таумономикон начинает с неё.
- Если запись открыта, первое нажатие Escape закрывает запись.
- Повторное Escape закрывает Таумономикон.
- ЛКМ и ПКМ работают для вкладок и исследований.
- Рецепты отображаются на классической сетке.
- У создаваемого предмета убрана лишняя обводка.
- Рамки исследований уменьшены.
- Новое доступное исследование мигает янтарной штатной рамкой.
- Дополнительная квадратная обводка вокруг исследования удалена.
- Поддерживается разметка страниц:
  - `<br>` и `<BR>`;
  - `<img>`;
  - `<LINE>`;
  - используемые классические теги и форматирование текста.
- Исследования поддерживают:
  - `parents`;
  - `hidden_parents`;
  - `revealed_by`;
  - критерии сканирования;
  - критерии варпа;
  - произвольные вложенные условия;
  - `concealed`;
  - `auto_unlock`;
  - `inactive`.
- Debug-флаг показа дерева:
  `research.debugShowAllResearch`.
- Debug сейчас должен быть выключен.
- `concealed=false` исследования показываются по умолчанию.
- Исследования отсутствующего игрового контента имеют `inactive=true`,
  отображаются серыми и не открываются.
- Такие исследования не выдают записку.
- Скрытые исследования появляются после выполнения родителей и условий.
- Вкладка скрывается только тогда, когда в ней действительно нет ни одного
  видимого исследования.
- Серые `inactive=true` исследования временно отсутствующего контента
  сохраняют вкладку видимой, но сами остаются недоступными.
- Когда в категории появляется любое видимое исследование, включая временно
  недоступное, вкладка появляется автоматически.
- Завершённое исследование сохраняет вкладку видимой.
- Если сохранённая последняя вкладка скрылась, выбирается первая доступная.
