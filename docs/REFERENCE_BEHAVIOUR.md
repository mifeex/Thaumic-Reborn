# Эталонное поведение первой вертикали

Этот документ фиксирует проверяемую связь между Thaumcraft 4.2.3.5 для
Minecraft 1.7.10 и первой вертикалью Thaumic Reborn для Forge 1.20.1.
Он не является общим описанием всего TC4: область ограничена аспектами,
Thaumometer, Research Table, research notes, Thaumonomicon и стартовыми
кристаллами.

## Источник и виды доказательств

Эталонный архив:
`reference/original/Thaumcraft_1.7.10_4.2.3.5.jar`.

SHA-256 архива:
`3dba9786966974701578a658d1bb369bf35bdf5f363079f5ac9c4910a39113be`.

В таблицах используются следующие виды доказательств:

- **BYTECODE** — результат чтения class-файла через
  `javap -p -c -constants`; подтверждает исполнявшуюся логику, но не
  называет обфусцированные Minecraft-методы их современными именами.
- **RESOURCE** — файл непосредственно внутри эталонного JAR: текстура,
  звук, OBJ, `sounds.json` или `.lang`.
- **MODERN SOURCE** — проверка текущего исходного кода порта.
- **UNIT SOURCE** — для правила существует unit-тест в `src/test`, но само
  наличие файла не считается результатом запуска тестов.
- **GAMETEST SOURCE** — Forge GameTest описывает интеграционную проверку, но
  наличие метода также не означает, что `runGameTestServer` был выполнен.
- **GAMETEST** — указанный Forge GameTest выполнен в текущем snapshot.
- **RUNTIME REQUIRED** — вывод нельзя считать подтверждённым без загрузки
  ресурсов в клиенте, dedicated server или реальной multiplayer-сессии.

| Старое хранилище `PlayerKnowledge` и sync-пакеты | Отдельно сохраняются открытые аспекты, их запас, сканы и завершённые исследования. | Capability `PlayerThaumKnowledge`: `known_aspects`, `aspect_amounts`, `scans`, `completed_research`, reveal/criteria/warp, `version=3`; данные порта `version=1` и `version=2` мигрируют без сброса ранее записанного знания. | **BYTECODE + MODERN SOURCE + UNIT SOURCE**: NBT round-trip, обе миграции и защита версии описаны тестами. |---|---|---|---|

Выпавший `BlockItem` переиспользует block definition, если отдельного item definition нет. | **BYTECODE + MODERN SOURCE + GAMETEST SOURCE**. Phenomenon/node scan намеренно вне первой вертикали; реальный dropped-item raycast требует client-проверки. |
| Classic object tags / aspect registration | Аспекты цели задавались таблицами TC4; универсальный вывод по современным Minecraft tags не является классическим правилом. | `ScanRegistry.find` сначала использует явный datapack JSON. В resources находятся 140 явных определений; 259 неадаптированных legacy scans остаются inactive. Текущий серверный и multiplayer runtime ещё требуется. |
| `ItemThaumometer.onUsingTick` | Через тик звучит `thaumcraft:cameraticks`, volume `0.2`, pitch `0.45 + random(0..0.1)`. | Клиентская ветка `ThaumometerItem.onUseTick` локально проигрывает ticks с теми же периодом, volume и диапазоном pitch; сервер сохраняет авторитет над прогрессом и отправляет финальный `cameraclack`. | **BYTECODE + RESOURCE + MODERN SOURCE**. Акустическое соответствие нужно слушать в игре. |
| `ScanManager.validScan` | Пустой aspect list даёт `tc.unknownobject`; неизвестные родители составного аспекта дают `tc.discoveryerror`; повторный объект не награждается. | `ScanService.complete` отклоняет неизвестную definition, неизвестный аспект и недостающих родителей. Для уже записанного `scanKey` повторное начисление запрещено. Пока Таумометр удерживается, каждый блок под прицелом получает контур и подпись без отдельного мирового луча; сохранённый `scanKey` немедленно открывает readout без повторного таймера. | **BYTECODE + MODERN SOURCE**. Клиент получает scan definitions вместе с knowledge sync; внешний вид контура требует client-проверки. |
| `ScanManager.completeScan`, `checkAndSyncAspectKnowledge` | Успех записывает скан, открывает аспекты и начисляет aspect points; первое открытие аспекта даёт дополнительный бонус `+2`. | Порт записывает scan key и атомарно начисляет data-driven количество каждого аспекта. По утверждённому правилу порта первое открытие получает `target amount + 3` (намеренное отличие от TC4); известный аспект получает только `target amount`. Неизученная цель показывает только имя; у изученной цели аспекты видны постоянно. Строка результата показывает фактически начисленное количество с учётом бонуса. | **BYTECODE + MODERN SOURCE + UNIT SOURCE**: отдельные тесты проверяют `+3`, отсутствие повторного бонуса, несколько новых аспектов и дублированные записи. Cap пула TC4 пока не воспроизведён. |
| `PacketScannedToServer.onMessage` | Старый пакет доверяет присланным dimension/player/target данным и не перепроверяет held item, LOS, дистанцию и время. Это историческая уязвимость, а не поведение для копирования. | В порте клиент не присылает готовый результат скана: `ThaumometerItem` создаёт серверную сессию, а сервер повторно проверяет hand, dimension, chunk, distance, LOS, identity и stable duration. | **BYTECODE + MODERN SOURCE + UNIT SOURCE**: все причины `ScanValidation` имеют unit-тесты. Реальная защита от задержки/спама требует multiplayer-теста. |
| `PacketAspectDiscovery`, `PacketAspectPool`, клиентские FX | Открытие сопровождается уведомлением, `random.orb` и руническими частицами; окончание скана — camera sound. | Отдельные toast/actionbar уведомления удалены: результат виден только внутри Таумометра. Vanilla hotbar и имя выбранного предмета остаются видимыми. Сохранены 24 `ENCHANT` particles и `cameraclack`. | **BYTECODE + RESOURCE + MODERN SOURCE**. Частицы являются современной аппроксимацией, не точной копией TC4 runes; HUD требует client-проверки. |

## Ограничение NODEJAR, подтверждённое TC4

Классические данные и bytecode задают одновременно следующие ограничения:

- wooden wand rod хранит `25` vis каждого примала;
- iron wand cap имеет consumption modifier `1.1`;
- `NODEJAR` требует `70` каждого примала, поэтому базовая конфигурация должна
  оплатить `77` каждого примала;
- research progression идёт
  `NODES → NODETAPPER1 → NODEPRESERVE → NODEJAR`;
- условие `NODEPRESERVE` не допускает wooden rod и iron cap;
- рецепт Goggles of Revealing выполняется на Arcane Workbench.

Следовательно, basic iron-capped wooden wand не способен выполнить точный
`NODEJAR`, а предложенный порядок, в котором Goggles идут до Arcane Workbench,
не является достижимым классическим survival-потоком. Значения не ослаблены:
по решению владельца scope зарегистрирован готовый empty Silverwood wand с
классической capacity `100` и iron cap. У него нет recipe, Infusion progression
или дополнительных caps. После зарядки такой wand способен оплатить точные
`77` каждого примала для реализованного `NODEJAR`.

## Что этим документом не подтверждено

- Реальный внешний вид GUI на разных GUI scale и разрешениях.
- Поведение capability после сохранения и повторного открытия мира.
- Корректность menu/container при двух игроках и злонамеренных packet/button ID.
- Обычный dedicated-server startup и подключение клиента.
- Полный TC4 parity за пределами первой вертикали.
- Право публично распространять классические ресурсы.

Автоматические результаты текущей сборки фиксируются после финального прогона
отдельно от ручной приёмки. Обычный dedicated server, save/reload мира,
multiplayer Play Mode и визуальный проход самого игрового цикла нельзя
заменять компиляцией, unit-тестами или GameTest.
